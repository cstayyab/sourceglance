# UI design — v0.1.0

Follows the [GNOME HIG](https://developer.gnome.org/hig/) and existing Shell menus (Quick
Settings, Calendar) for spacing and type. Requirement IDs (R1–R9) refer to the
[roadmap](../product/roadmap.md).

## Top-bar indicator (R6)

```
 ┌───────────┐
 │  ☑  7     │   icon + count label
 └───────────┘
```

- Icon: `checkbox-checked-symbolic` (ships with Adwaita icons, so no custom assets yet).
- Count label: shown only when signed in and count > 0. Shows `25+` if the search
  reports more results than were fetched.
- Error state: icon gets the `.sourceglance-error` style (dimmed); no count.
- Accessible name: "sourceglance: 7 assigned issues" (or the state message).

## Menu — signed in (R3, R5, R7)

```
┌──────────────────────────────────────────────┐
│ @omer-gh · updated 2 min ago                 │  header, dim, not clickable
├──────────────────────────────────────────────┤
│ omer-gh/sourceglance                            │  repo heading, bold, not clickable
│   #12  Store token in GNOME keyring          │  issue row → opens in browser
│   #9   Show count badge on panel icon        │
│ acme/api                                     │
│   #431 Retry on 502 from upstream gatewa…    │  titles truncated at 48 chars
├──────────────────────────────────────────────┤
│ View all on GitHub                           │  github.com/issues/assigned
│ Refresh                                      │
│ Settings                                     │
└──────────────────────────────────────────────┘
```

- Issues sorted by most recently updated; repos ordered by their newest issue.
- At most 25 issue rows; if there are more, "View all on GitHub" says "View all 31 on
  GitHub".
- Clicking an issue closes the menu and opens the issue URL.
- While a refresh runs, the header reads "Refreshing…" and the **Refresh** item is
  insensitive.

## Menu — other states (R8)

| State | Header / body text | Actions shown |
|-------|--------------------|---------------|
| Signed out | "Sign in to see your GitHub issues" | Settings |
| Loading (first fetch) | "Loading issues…" | Settings |
| Empty | "No open issues assigned to you" | View all on GitHub, Refresh, Settings |
| Invalid token (401) | "Your token was rejected. Update it in Settings." | Settings |
| Rate limited (403/429) | "GitHub rate limit reached. Retrying at HH:MM." | Settings |
| Offline / other | "Couldn't reach GitHub. Retrying in N min." | Refresh, Settings |

On error, the last successful list stays visible below the message, if there is one.

## Settings window (R1, R2, R4)

One page, **General**, with two groups:

**Account**

| Row | Widget | Behaviour |
|-----|--------|-----------|
| Status | `Adw.ActionRow` | "Signed in as @login" or "Not signed in" |
| Personal access token | `Adw.PasswordEntryRow` with apply button | On apply: validate with `GET /user`; on success save to keyring and update status; on failure show a toast with the reason. The field is cleared after saving and the token is never shown again. |
| Create a token | `Adw.ActionRow` link | Opens GitHub's fine-grained token page; subtitle says which permissions to grant: *Issues: Read*, *Metadata: Read*, on the repos you want. |
| Sign out | destructive button | Removes the token from the keyring. Visible only when signed in. |

**Issues**

| Row | Widget |
|-----|--------|
| Repositories to watch | `Adw.EntryRow`, comma-separated `owner/name`; empty means all |
| Refresh interval | `Adw.SpinRow`, 1–120 minutes, default 10 |
