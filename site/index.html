See it on your desktop

Everything assigned to you, without the tab hunt

Top-bar buttons

Issues, Pull requests and Projects as one tinted group or as tabs, each with its live count. Filter by label; closed items are counted at the bottom.

Act from the menu

Comment, close or reopen, edit assignees and labels, and move items between statuses on your project boards.

GitHub and GitLab

gitlab.com issues and merge requests get their own collapsible section in every list, and the counts add up across both.

Main window

A full window with your lists and settings in a sidebar, opened from the app grid with a splash screen, in the top bar's blue.

Desktop widgets

Summary, Issues, Pull requests and Projects cards on your desktop. Drag them anywhere and set their opacity.

Private by design

Signs in through a GitHub App limited to issues, pull requests and projects: no code access. Tokens stay in the GNOME keyring.

Install in three steps

  1. Download Setup

    sourceglance Setup for Intel/AMD works on most PCs; there's also a build for ARM.

  2. Allow it to run

    In Files, right-click the download, choose Properties and turn on Executable as Program.

  3. Run the wizard

    Double-click it and follow the steps. Run it again any time to repair or remove sourceglance.

Check the download (recommended)

Download SHA256SUMS into the same folder and run:

sha256sum --check --ignore-missing SHA256SUMS

Every release is built by GitHub Actions with a provenance attestation. See the install guide.

Needs GNOME Shell 46–50 (Ubuntu 24.04 or newer) and a GitHub or GitLab account.

Update, repair or remove

One Setup file does it all. Download the latest Setup and run it: it finds the sourceglance you have and updates it in place, keeping your settings and sign-ins. Run it again any time to repair or remove sourceglance.

sourceglance shows Update available in its window's title bar when a newer version is out. Turn this off in Settings → System Start.

Get involved

sourceglance is open source. Found a bug or have an idea? Tell us, or fork the repository and send a pull request.

Report an issue Fork on GitHub
  1. Fork the repository and clone your fork.
  2. Create a branch, make your change, and run make lint and make test.
  3. Push to your fork and open a pull request against main.
